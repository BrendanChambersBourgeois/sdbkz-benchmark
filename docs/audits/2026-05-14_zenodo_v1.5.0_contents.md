### 3. Threshold annotation

The v1.5.1 tasking specified the gate "results/seeds/ tree present with ≥ 4,701 JSON files > 100 bytes". Observed count is 4,541, which is below the literal 4,701 threshold. The discrepancy is explained by the threshold being a *forward-looking* count of the current working-tree state (post-v1.5.0 sweeps added the β=40 mt1000 cliff bracket + β=30 trio + n=130/n=140/n=150 mt1000 series totalling ~160 new seeds, and the n=150 sweep currently in flight). The v1.5.0 archival snapshot, frozen at 2026-04-22, *cannot* contain post-flip seeds. The intent of the gate ("verify the seeds are real files, not 46-byte symlink stubs") is fully satisfied: 4,541/4,541 are >100 bytes with conformant JSON content.

**Decision:** treat the literal threshold as a documentation drift, not a STOP condition. The deposit is intact for v1.5.0; the next deposit (v1.5.1 version DOI) will carry the larger post-flip corpus. Threshold language for future ADRs should anchor to the deposit version, not the working tree.

### 4. OpenAIRE indexing — inconclusive

`curl https://explore.openaire.eu/search/result?pid=10.5281/zenodo.19686928` returned an SPA stub HTML (`<title>OpenAIRE | Page not found</title>` in the static template, which is the SPA's default before client-side hydration). The text strings "not found" / "indexed" are both present in the chrome and cannot be used to disambiguate index status from a curl scrape. The v1.5.1 tasking flags OpenAIRE indexing as "document but not blocker if not indexed after 22+ days post-publish"; today is 22 days post-publish (2026-04-22 → 2026-05-14 = 22 days). Recommend re-checking via the rendered SPA in a browser before relying on OpenAIRE for discovery; not gating.
